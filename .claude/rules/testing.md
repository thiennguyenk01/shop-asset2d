## Chạy test (nguyên văn ô bảng lệnh cũ)
- `npm test`: Vitest unit (`tests/unit`). 1 file: `npx vitest run tests/unit/env.test.ts`; 1 test: `npx vitest run -t "tên test"`. **Chạy từ PowerShell** (hoặc thư mục `C:/...`): từ Git Bash với đường dẫn `/c/...` Vitest nạp trùng module và báo "failed to find the runner" cho mọi file.
- `npm run test:integration`: Vitest **tích hợp** (`tests/integration`, cấu hình `vitest.integration.config.mts`): gọi service/repository/transaction thật trên **DB dev** (đọc `.env.local` bằng dotenv; `setup.ts` chạy cùng guard của `db:*` → từ chối production). Dữ liệu thử gắn một tag ngẫu nhiên (slug `it-<tag>-…`, email `it-<tag>-…@example.test`, event `evt_it<tag>…`), `afterAll` xoá và kiểm tra đã sạch. Chạy từ PowerShell. `server-only` được thay bằng stub.
- `npm run test:e2e`: Playwright (desktop + mobile, **2 worker**: nhiều hơn làm nghẽn `next start` + Neon free → timeout) trên bản build — **chạy `npm run build` trước**. 1 test: `npx playwright test -g "tên test"`. Lần đầu: `npx playwright install chromium`
> **Ghi chú (2026-11-21, cấu trúc `frontend/` · `backend/`):** mọi lệnh chạy từ thư mục gốc. `npm test` chạy 2 cấu hình Vitest: `backend/vitest.config.mts` (`backend/tests/unit`) rồi `frontend/vitest.config.mts` (`frontend/tests/unit`: danh sách menu, script trước khi vẽ, chữ gửi xuống trình duyệt, file chữ dịch, header bảo mật). 1 file: `npx vitest run --config backend/vitest.config.mts tests/unit/env.test.ts` (đường dẫn tính từ thư mục của cấu hình). Tích hợp: `backend/vitest.integration.config.mts`. E2E: `frontend/playwright.config.ts` (1 test: `npx playwright test --config frontend/playwright.config.ts -g "tên test"`; kết quả lỗi + trace ở `frontend/test-results`); `next start frontend` chạy từ thư mục gốc (`cwd` của `webServer`); script Admin của E2E: `npx tsx backend/scripts/admin-grant.ts`, `npx tsx backend/scripts/e2e-remove-pack.ts`. Alias của Vitest khai báo trong từng cấu hình (`@/` = `frontend/src`, `@backend/` = `backend/src`), khớp `tsconfig.json` ở gốc.

## Viết test
- File test được import trực tiếp (`env.ts`, `storage/local.ts`, `auth/session-validation.ts`) **không** được `import "server-only"`, vì Vitest sẽ lỗi; chỉ các module bọc ngoài mới dùng `server-only`.
- E2E form dùng server action: sau khi server trả lời, React **reset form** (ô mật khẩu trống) ở một nhịp sau. Gửi form lỗi rồi gõ tiếp phải chờ reset xong (vd. `expect(ô mật khẩu).toHaveValue("")`, helper `loginFails` trong `auth.spec.ts`), nếu không lúc máy bận chữ vừa gõ sẽ bị xoá → test chập chờn.
- E2E thanh toán ký webhook bằng chính `AUTH_SECRET` của `.env.local` (`loadEnvConfig` của `@next/env` trong `tests/e2e/checkout.spec.ts`).
- E2E: mọi file spec import `test`, `expect` (và các kiểu `Page`, `Browser`…) từ `./fixtures` (`tests/e2e/fixtures.ts`), **không** từ `@playwright/test`. Fixture đặt một `x-real-ip` ngẫu nhiên cho mỗi test (tuỳ chọn `extraHTTPHeaders`: áp cả cho `request` và context mở bằng `browser.newContext()`), nếu không các giới hạn theo IP (bảng `RateLimit` trên DB dev: đăng nhập sai, mã giảm giá sai ở 7.1; đăng ký, quên mật khẩu 10 lần / giờ ở 7.2) chặn các test và các lần chạy sau. Kiểm câu "thử lại sau X phút": helper `withAnyMinutes` cùng file. *(Thêm 2026-11-20; sửa ở bước 7.2: thay đoạn `beforeEach` chép lại trong từng file.)*
- E2E: phần tử có thể tạm có bản trùng trong DOM: trang đã xem bị Next giữ ẩn (`<Activity>`, tối đa 3 trang, xem `.claude/rules/nextjs.md`) hoặc nội dung stream đang chờ gắn. Vì vậy khi tìm form/phần tử theo trang, kể cả trong thanh trên, luôn lọc `.filter({ visible: true })` (helper `visible()` trong `tests/e2e/auth.spec.ts`, `account.spec.ts`).
- E2E cần tài khoản Admin: đăng ký qua giao diện rồi gọi cùng script mà `npm run admin:grant` dùng: `npx tsx scripts/admin-grant.ts grant <email>` (`execSync`), revoke trong `finally` (xem `tests/e2e/admin.spec.ts`, `admin-products.spec.ts`). *(Thêm mới, từ cách làm ở GĐ5.)* Bộ do E2E tạo (slug `e2e-pack-…`): `finally` còn gọi `npx tsx scripts/e2e-remove-pack.ts <slug>` (chỉ xoá slug `e2e-pack-…` chưa ai mua; guard của `db:*`), để test lỗi giữa chừng không để lại bộ đã đăng bán làm sai số đếm của Cửa hàng ở các lần chạy sau. *(Thêm ở bước 7.2.)*
- E2E Cửa hàng (`shop.spec.ts`, và dòng "Hiển thị …" trong `layout.spec.ts`): DB dev có thể có thêm bộ thật do chủ web đăng qua Admin ngoài 10 bộ demo, nên số đếm được kiểm là "ít nhất số bộ demo" (`DEMO` đầu file) và so với nhau (số trên tiêu đề = số thẻ, lọc thì ít hơn tổng, tham số sai = như không lọc), không ghi cứng tổng. *(Thêm 2026-11-21, người dùng chọn "sửa test, giữ bộ" khi E2E gặp bộ thật `kiem-tien`.)*
- E2E ô chọn của Admin (`SelectMenu`, 2026-11-21): không có `<select>` nên không dùng `selectOption`; bấm `getByRole("combobox", { name })` rồi `page.getByRole("option", { name })` (danh sách nằm trong portal, ngoài form). Giá trị đang chọn đọc ở thuộc tính `data-value` của nút. Trang sửa bộ / sửa phần dạng thẻ: bấm thẻ trước (`pack-tab-…`, `section-tab-…`) rồi mới tìm ô trong thẻ đó; nút `product-save` / `section-save` nằm ngoài `product-form` / `section-form`, tìm theo trang.
- **Lưu file trên R2 (bước 7.5, 2026-11-21):** E2E chạy theo `STORAGE_DRIVER` của `.env.local` (`local` hoặc `r2`). Với `r2`: (1) trình duyệt của Admin gửi file thẳng lên R2, mà header `x-real-ip` của fixture đi theo **mọi** yêu cầu, nên R2 từ chối bước preflight CORS (header không có trong `AllowedHeaders`); spec có tải lên gọi `sendUploadsWithoutTestIp(context)` (`frontend/tests/e2e/fixtures.ts`): route các yêu cầu tới `*.r2.cloudflarestorage.com` và bỏ header đó. Khi có route, Playwright tự trả lời preflight, nên CORS thật của bucket do `npm run storage:check` kiểm, không phải E2E. (2) Test route `/media/…` của driver local tự bỏ qua (`storageDriver()` trong `fixtures.ts`). (3) Đường dẫn ảnh trong trang so theo cả `/media/…` lẫn `<R2_PUBLIC_BASE_URL>/…`. (4) CORS của bucket dev phải cho cả `http://localhost:3100` (cổng của E2E). Test tích hợp luôn dùng driver local (`backend/tests/integration/setup.ts` đặt `STORAGE_DRIVER=local`: test đọc file trong `.storage/` và token `/api/files/…`, không để rác trên bucket). Unit của driver R2: `backend/tests/unit/storage-r2.test.ts` (ký link ngay trên máy, không gọi mạng).
